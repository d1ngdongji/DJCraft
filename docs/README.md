# DJCraft 文档索引

> 代码基线：DJCraft 2.1.1、Minecraft 1.21.1、NeoForge 21.1.218；核对日期：2026-08-02。

| 文档 | 面向对象 | 内容 |
|---|---|---|
| [游戏机制与实现文档](gameplay-mechanics.md) | 玩家、服主、整合包作者、开发者 | 完整游戏循环、会话、时间与判定、战斗、资源、移动、组网、HUD、统计、服务端权威及实现索引 |
| [曲目包功能文档](trackpack-feature.md) | 曲目作者、服主、开发者 | `track.json`、OGG、时间线、加载/哈希、下载、动态资源、格式限制及玩法字段边界 |
| [资源包开发文档](resource-pack.md) | 美术、音效、动画作者、附属 Mod | HUD/模型/声音覆盖、武器音效 Profile、第一人称动画、动态曲目资源边界 |
| [数据包开发文档](data-pack.md) | 整合包作者、服主 | 物品左右键冷却/切换前摇/能量成本、弓弩盾行为 Profile、配方覆盖、物品引用、标签边界与数据组件 |
| [附属 Mod 接口文档](addon-api.md) | Java/NeoForge 开发者 | 依赖、侧安全、物品行为注册/执行、事件、音效 resolver、曲目/会话查询、组件、属性与网络边界 |

选择方式：

- 要了解游戏怎么玩、规则如何结算或代码在哪里实现：先看游戏机制与实现文档。
- 要新增歌曲和节拍：使用曲目包，不是数据包。
- 要替换贴图、声音或固定第一人称动作：使用资源包。
- 要改物品 DJ 左右键冷却、切换前摇、动作能量成本、弓弩盾子类行为、配方，或在原版数据内容中引用 DJCraft 物品：使用数据包。
- 要响应节拍、适配自定义武器或读取会话：开发附属 Mod。

所有文档都以当前代码可达实现为准。标为“未完成”或“内部实现”的能力不应当作已支持的内容契约。

## 维护映射

| 功能改动范围 | 必须检查并按需更新的文档 |
|---|---|
| 玩家可见规则、游戏循环、会话生命周期、时间与判定、连击/容错/能量、战斗、盾牌、移动、被动物品、组网、HUD、唱片统计和服务端权威 | `gameplay-mechanics.md` |
| 曲目包格式、加载/校验/哈希、下载、动态资源、字段到玩法的边界和曲包限制 | `trackpack-feature.md` |
| 模型、纹理、语言、着色器、声音、武器声音配置、第一人称动画、客户端资源重载与覆盖优先级 | `resource-pack.md` |
| 配方、标签、战利品表或其他服务端数据资源，以及配置与数据包的边界 | `data-pack.md` |
| 事件、公开 Java 类型、管理器/查询入口、注册流程、网络边界、线程与逻辑侧约束、附属 Mod 兼容性 | `addon-api.md` |
| 文档新增、重命名、删除或职责范围变化 | `README.md` |

一次改动可能同时命中多行。例如新增可由附属 Mod 注册、并由资源包重载的曲目视觉配置时，应同时维护资源包文档和附属 Mod 接口文档。

## 维护规则

- 相关功能任务只有在代码与对应文档同步后才视为完成。
- 文档描述当前代码事实；规划、占位、部分实现或不可达流程必须标记为“**未完成**”。
- 未完成功能完成或实现范围变化时，必须同步更新状态、示例、限制和使用流程。
- 接口变更应写明类型或签名、资源标识、逻辑侧、调用时机、注册生命周期、兼容性影响和迁移方式。
- 资源/数据格式变更应写明完整路径、命名空间、字段结构、默认值、校验与回退、重载能力及覆盖优先级。
- 与这些行为和契约无关的任务无需制造无关文档改动。
